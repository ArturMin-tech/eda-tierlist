# Еда — тир-лист продуктов из доставки

Статический сайт на GitHub Pages: тёмный тир-лист (S/A/B/C/D/F) продуктов, которые пользователь заказывал. Данные потом пойдут на обучение AI-агента.

## Файлы
- `products.json` — каталог товаров. Генерируется `extract_products.py`, руками не править.
- `tiers.json` — оценки. Пишет **только сайт** (кнопка «Сохранить» коммитит через GitHub API). Не перезаписывать, перед правками в репо делать `git pull`.
- `images/<id>.png` — вырезки со скриншотов; `images_hd/<id>.*` — HD-фото из интернета (только 100% совпадение упаковки).
- `screenshots/` — исходные скриншоты заказов.
- `index.html`, `style.css`, `app.js` — сайт (SortableJS с cdnjs, без сборки).

## Еженедельный процесс (пользователь присылает скриншоты нового заказа)
1. `git pull` (на сайте могли появиться новые оценки).
2. Сохранить скриншоты в `screenshots/` с уникальными именами (например `2026-11-03_01.jpg`).
3. Сверить товары с `products.json`: уже существующие (по названию) не добавлять повторно.
4. Новые товары дописать в `ITEMS` в `extract_products.py` (y первой строки названия в координатах ширины 923px), запустить скрипт, проверить вырезки глазами.
5. Поискать HD-фото для новых товаров, сохранять только при точном совпадении упаковки (дизайн, размер, регион — Канада, Walmart через Instacart). Хорошие источники: Instacart CDN, Save-On-Foods `images.cdn.saveonfoods.com/zoom/<UPC14>.jpg`, Giant Tiger, сайты производителей. Перезапустить скрипт, чтобы проставился `image_hd`.
6. Закоммитить и запушить. Новые товары сами появятся на сайте в блоке «Не оценено».
